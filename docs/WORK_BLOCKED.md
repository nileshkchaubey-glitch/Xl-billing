# Blocked work and unsupported records

No development phase is stopped by the earlier audit. Conflicting nonempty payment histories are preserved and their payment mutations are blocked; the app does not invent missing receipts. Unsupported executable identifiers or malformed/unreadable collections remain intact with a visible error. Manual review of an owner's actual records is outside this task and was not performed.

Concurrent writers using older app versions cannot be assumed to cooperate with the future storage protocol. P0-6 must state that limitation. Browser/file lock capability was checked with fresh synthetic contexts in Chromium, Firefox and WebKit; all three acquired an exclusive lock successfully.
